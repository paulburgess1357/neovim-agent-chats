INTRODUCTION                                        *agent-chats-introduction*

agent-chats.nvim lists every chat of Claude Code, Codex, Qwen Code and
opencode in one place, shows which need you, and lets you open, reply to,
search and start chats from Neovim.

It reads what the agents already write to disk and listens to what they
report through their own hooks. It does not wrap how they are started, so
chats started anywhere are listed. It needs Neovim 0.11 or newer and nothing
else; a POSIX `sh`, `git`, `rg` and the system SQLite library are used when
present.

==============================================================================
SETUP                                                      *agent-chats-setup*
>lua
    require('agent-chats').setup()
<
`setup()` is optional. Without it |:Chats| still works; with it the plugin
also watches in the background, which drives notifications and the
statusline segment. Nothing is mapped globally; see |agent-chats-commands|
for `<Plug>` mappings.

Then, once: >vim
    :Chats hooks install
<
so that each agent reports its own status (|agent-chats-hooks|). The board
works without it, but for every agent except Claude Code "needs you" is then
a guess.

THE BOARD                                                  *agent-chats-board*

|:Chats| opens the board in its own tab: the list on the left, a pane on
the right. The pane follows the cursor. For a chat running in a terminal of
this Neovim it shows that live terminal; for any other chat it shows a
summary (what it waits on or is doing, last prompt, last reply). The pane's
title says which of the two it is.

Keys (all configurable through `keys`, see |agent-chats-options|):

    <CR> / o    Open the chat: its terminal, resuming it if it ended
    t           Read the whole conversation, tool calls folded
    r           Reply
    Q           Queue a reply for when the chat finishes its turn; with
                replies queued, also send or drop them
    n           New chat (agent, folder or new git worktree, first prompt)
    F           Fork the chat into a new one
    H           Hand the chat to another agent
    d           Show uncommitted changes in the chat's folder
    /           Filter the board: names, folders, branches, agents, labels,
                latest messages
    S           Search inside all conversations (starts from the filter)
    <Esc>       Clear the filter, then the search
    b           Group by status, folder, agent or worktree
    <Tab>       Fold a group, or show a chat's subagents
    p           Show or hide the pane
    u / U       Mark read or unread / mark everything read
    P           Pin to the top of its group
    a / A       Archive / show archived and older chats
    l / e / R   Edit labels / edit the note / rename
    y / Y       Copy the resume command / copy the id
    ]a / [a     Next / previous chat that needs you
    <C-f> <C-b> Scroll the pane
    <C-r>       Refresh now
    gh          Set up the agents' status hooks
    g?          Show the keys
    q           Close the board (terminals keep running)

In a chat's terminal in the pane, `<C-\><C-b>` goes back to the list
(`open.back_key`).

In a conversation: `q` goes back to the list, `r` replies, `]]` and `[[`
move between your prompts, and the usual fold commands open tool calls.

`/` narrows what is on the board as you type; it looks at what the rows
already show. `S` reads the conversations themselves and lists the matching
passages under their chats. A search starts from every chat, so it drops the
filter; a filter typed afterwards narrows the results.

Replying. `r` sends now: pasted into the chat's terminal when it runs in
this Neovim, or by resuming the chat when it has ended (`reply.ended`). `Q`
queues the reply behind the turn that is running, and it is pasted in when
that turn ends.

A reply is pasted, never typed as keys, and Enter is pressed only once the
terminal shows the text (`reply.echo_wait`). An agent that is showing a
dialog of its own (trust this folder, update available, a permission
prompt) does not take a paste: then nothing is sent and you are told. A
chat that shows as "Needs you" is not pasted into at all; you are taken to
it to answer first.

A queued reply is only ever pasted into a terminal of this Neovim that
still has the chat in it, and never starts an agent by itself. If the chat
ends first its replies are kept, you are told, and from then on they go
only when you say so: `Q` on the chat sends them, carries on, or drops
them. Opening the chat again does not send them. A reply you wrote and did
not send is offered again the next time you reply to that chat.

A new chat that has not been sent a prompt is listed as "(no prompt yet)"
until its agent names it, so a row always leads back to its terminal.

COMMANDS                                                *agent-chats-commands*

                                                           *:Chats* *:AgentChats*
:Chats                  Open the board, or go to it.
:Chats new [agent]      Start a new chat.
:Chats next             Jump into the chat that has waited for you longest.
:Chats search [text]    Search inside all conversations.
:Chats filter {text}    Open the board filtered.
:[range]Chats send      Send the lines, with file name and line range, to a
                        chat running in this Neovim.
:Chats hooks            Overview of the status hooks, with keys to install
                        and remove them.
:Chats hooks install [agent ...]
                        Install hooks for the agents named, or for every
                        agent in use. Shows the changes and asks first.
:Chats hooks uninstall [agent ...]
                        Remove them again.
:Chats hooks show [agent ...]
                        The steps to install them by hand.
:Chats hooks status     One line per agent.
:Chats refresh          Look for changes now.
:Chats close            Close the board.
:Chats health           Run `:checkhealth agent-chats`.

`:AgentChats` is the same command under a second name.

Mappings to bind yourself:

    <Plug>(agent-chats)          Toggle the board
    <Plug>(agent-chats-next)     Next chat that needs you
    <Plug>(agent-chats-new)      New chat
    <Plug>(agent-chats-search)   Search conversations
    <Plug>(agent-chats-send)     Send the selection to a chat (visual mode)

STATUS HOOKS                                               *agent-chats-hooks*

Each agent has an official way to tell other programs what it is doing.
Claude Code, Qwen Code and Codex run a command on events such as "about to
ask for permission" and "turn finished"; opencode hands its events to a
plugin file. `:Chats hooks install` sets these up:

    Claude Code   `hooks` in ~/.claude/settings.json. Running sessions pick
                  them up at once.
    Qwen Code     `hooks` in ~/.qwen/settings.json. New sessions; or open
                  /hooks once in a running one.
    Codex         ~/.codex/hooks.json. Codex runs a hook only after you
                  trust it: it asks the next time it starts ("Hooks need
                  review"), or run /hooks.
    opencode      ~/.config/opencode/plugins/agent-chats.js. New sessions.

The installer shows a diff of every file it would touch and asks. It edits
the file as text, so key order, indentation, comments and your own hooks
stay as they were; it checks that the result parses, that nothing but its
own entries differs and that every comment is still there; and it first
keeps the old file beside the new one as
`<file>.agent-chats-backup-<date>-<time>.<n>` (the last three are kept).

It leaves a file alone, and says why, when the file is not valid JSON,
cannot be read, is read-only, or changed while the diff was on screen. A
symlinked settings file stays a symlink and is edited where it points; a
link to nothing is left alone. opencode's plugin file, when it is a link
you made, is never written through: uninstalling removes the link only.
With no agent named, only agents whose own folder exists are set up.
Uninstalling takes out what was put in.

The hook is one POSIX shell script, copied to
~/.local/share/agent-chats/agent-chats-hook.sh (`hooks.script`). It appends
one line per event to ~/.local/state/agent-chats/events/<agent>/<session>.log
(`hooks.dir`): the time, the event's name and, when present, the
notification type, the tool's name, the subagent id, why the session
started or ended and the agent's process id. Prompts, replies, commands and
tool output are never stored. The script prints nothing and always exits 0.
The installed command is >
    AGENT_CHATS_EVENTS_DIR=<folder> sh <script> <agent> 2>/dev/null || true
<so it cannot block or fail the agent, and it writes where this Neovim
reads whatever the agent's environment is. It works whether or not Neovim
is running.

Entries made by hand are recognised as long as the command runs
`agent-chats-hook.sh` with the agent's name, ends in `|| true`, and writes
to the folder this Neovim reads (without `AGENT_CHATS_EVENTS_DIR=` that is
~/.local/state/agent-chats/events, or under $XDG_STATE_HOME).
`:Chats hooks status` and `:checkhealth` say so when the two differ.

From a script, without the question: >lua
    require('agent-chats.hooks').install()          -- every agent in use
    require('agent-chats.hooks').install({ 'codex' })
    require('agent-chats.hooks').uninstall()
<
==============================================================================
STATUSES                                                  *agent-chats-status*

    Needs you       The agent is blocked on you (permission, a question)
    Working         The agent is mid-turn
    Done, unread    The turn finished and you have not looked since
    Idle            Finished, seen, the agent is still open
    Ended           No process has the chat open; it can be resumed

What a chat is doing is known three ways, the most direct that has spoken
being believed: the agent's hooks (|agent-chats-hooks|); an interface of
the agent that can be asked; and files and processes (the transcript, a
session registry, the process table).

Without hooks, Claude Code's session registry makes "Needs you" exact. For
the other agents it is then a guess: a tool call with no result and nothing
written for `status.stall_after` seconds. A long-running command looks the
same, so those chats are marked with a question mark and raise no
notification unless `notify.inferred` is set.

What hooks do not say: that you answered a prompt (the next news is the
tool finishing; Claude Code's registry fills that gap, and for a chat in a
terminal of this Neovim typing into the terminal counts as the answer), and,
for Claude Code and Qwen Code, that you interrupted a turn (the transcript
says so, and wins when it shows the turn over after the hooks last spoke).

The pane says where a running chat's status comes from, and
`:checkhealth agent-chats` says it per agent.

OPTIONS                                                  *agent-chats-options*

Pass any of these to `setup()`; the values shown are the defaults.
>lua
    {
      providers = {
        claude   = { enabled = true, cmd = { 'claude' },   home = nil, headless_args = {} },
        codex    = { enabled = true, cmd = { 'codex' },    home = nil, headless_args = {} },
        qwen     = { enabled = true, cmd = { 'qwen' },     home = nil, headless_args = {} },
        opencode = { enabled = true, cmd = { 'opencode' }, home = nil, headless_args = {} },
      },
      board = {
        layout = 'tab',         -- 'tab' | 'float' | 'current'
        width = 0.92, height = 0.88, border = nil,   -- float
        pane = true, pane_size = 0.5,
        group_by = 'status',    -- 'status' | 'folder' | 'provider' | 'worktree'
        max_age_days = 30,      -- 0 shows everything
        max_per_group = 40,
        spinner = true,
      },
      open = {
        where = 'pane',         -- 'pane' | 'vsplit' | 'split' | 'tab' | 'float'
                                -- | 'current' | function(ctx) -> buffer
        size = 0.4, start_insert = true, close_on_exit = true, reuse = true,
        back_key = '<C-\\><C-b>',
      },
      status = { stall_after = 30, working_timeout = 900 },
      hooks = { enabled = true, dir = nil, script = nil, remind = true },
      watch = { enabled = true, interval = 2000, background_interval = 5000,
                scan_interval = 30000 },
      notify = { enabled = true, attention = true, done = true, inferred = false,
                 scope = 'all', desktop = false, handler = nil },
      reply = { ended = 'ask', paste_delay = 120, echo_wait = 2000 },
      worktree = { path = '{parent}/{repo}.worktrees/{name}', base = nil },
      transcript = { tool_output_lines = 30, thinking = false, fold_tools = true },
      search = { max_hits = 5, tools = false },
      diff = nil, state_file = nil, cache_file = nil,
      icons = { ... }, keys = { ... },
    }
<
`providers.<name>.cmd` is how the agent is started; add flags there rather
than relying on a shell alias. `headless_args` are added to background
replies, for example to choose a non-interactive permission mode.
`providers.opencode.config_dir` says where opencode keeps its config when
that is not ~/.config/opencode.

`hooks.enabled = false` ignores what installed hooks report. `hooks.dir` is
where they write and `hooks.script` where the script is kept; after
changing either, install again (the status says "outdated" until then).
`hooks.remind = false` drops the board's line about agents that can only
guess.

`open.where` as a function receives `{ argv, cmdline, cwd, env, title,
chat }`, opens a terminal and returns its buffer.

`notify.scope` limits notifications to chats under the working directory
("cwd") or to chats running in this Neovim ("hosted").

`keys` maps action names to a key, a list of keys, or false. The action
names are those of |agent-chats-board|: open, transcript, pane, reply,
queue, new, fork, handoff, diff, filter, search, clear, group, toggle,
unread, read_all, pin, archive, show_all, label, note, rename, yank,
yank_id, next_attention, prev_attention, scroll_down, scroll_up, refresh,
hooks, help, close.

Highlight groups start with `AgentChats` and link to standard groups.

LUA API                                                      *agent-chats-api*

    require('agent-chats').setup({opts})
    require('agent-chats').open({opts})     -- { layout, group_by, filter }
    require('agent-chats').close()
    require('agent-chats').toggle()
    require('agent-chats').new({opts})      -- { provider, cwd, prompt }
    require('agent-chats').next()
    require('agent-chats').search({text})
    require('agent-chats').send({text})
    require('agent-chats').refresh()
    require('agent-chats').hooks({action}, {names})
    require('agent-chats').counts()         -- { attention, working, done, idle, ended }
    require('agent-chats').statusline()     -- e.g. "● 2  ◐ 3  ✓ 1", or ""
    require('agent-chats').chats()          -- every chat in the index
    require('agent-chats').register({provider})

User autocommands: `AgentChatsUpdate`, and `AgentChatsAttention` /
`AgentChatsDone` with `data.key` and `data.chat`.

ADDING AN AGENT                                        *agent-chats-providers*

An agent is a table with these fields, passed to `register()`:

    name, label     Short id and display name.
    home()          Where the agent keeps its data.
    available()     Whether there is anything to read.
    discover()      One `{ id, path?, mtime, size, data? }` per chat. Cheap:
                    no file is opened.
    parse(entry, prev)
                    Called when an entry's mtime or size changed. Returns
                    `{ title, first_prompt, last_prompt, last_reply, cwd,
                    branch, model, created, updated, turn, turn_at,
                    activity, pending_tool, asking, parent_id }`, where
                    `turn` is "working", "waiting", "done", "aborted" or
                    "unknown". Returns nil for a chat with no conversation.
    messages(chat, opts)
                    The conversation after `opts.cursor`, plus a new cursor
                    (nil when it cannot read incrementally), plus true when
                    it had to start again from the top. Raises an error when
                    the conversation cannot be read. Messages are
                    `{ role, text, name, summary, input, lang, error, id,
                    time }` with role "user", "assistant", "thinking",
                    "tool", "tool_result" or "system".
    resume_cmd(chat), new_cmd(opts)
                    Argument lists that resume a chat and start a new one.

Optional. The first three are the ways a chat's status can be known; supply
any of them:

    hooks           `{ events, process?, config? }`. `events` maps the
                    names of the agent's hook events to what they mean:
                    "working", "active", "waiting", "resolved", "done",
                    "idle", "aborted", "start" or "ended"; or to a function
                    of the event that returns one. The agent runs
                    scripts/agent-chats-hook.sh with its name, and JSON on
                    standard input or the event and session id as
                    arguments. `config()` says how `:Chats hooks install`
                    sets that up.
    query(chats)    `{ [id] = { pid, turn?, turn_at?, ... } }` from a CLI
                    or API of the agent. Called at most every
                    `query_interval` ms.
    live(chats, reported)
                    The same from files and processes, on every refresh.
    locate(id, live)
                    The entry of a running chat not yet discovered.
    subagents(chat) Chats spawned by a chat.
    grep(query)     Ids of chats that may contain the text, for agents with
                    no transcript file per chat.
    rev(id)         A value that changes when something about the chat
                    changed outside its transcript (a title kept elsewhere).
    check()         Extra lines for `:checkhealth`.
    fork_cmd(chat), headless_cmd(chat, prompt), resume_prompt_cmd(chat, prompt)
    exact           `live()` reports the turn state itself.
    preassign_id    `new_cmd` honours `opts.id`.

The annotated contract is in `lua/agent-chats/types.lua`,
`lua/agent-chats/providers/claude.lua` is the reference implementation, and
the README has a complete small provider.

==============================================================================
LIMITS                                                    *agent-chats-limits*

- A chat running outside this Neovim can be read but not typed into.
- Background replies cannot answer permission prompts.
- Queued replies are pasted into a terminal of this Neovim, or not sent: a
  chat that ended keeps its queue until you send or drop it with `Q`.
- A dialog an agent shows is only known when the agent reports it. For any
  other (an update offer, a trust question) a reply is not sent, because
  the pasted text does not appear; you are told to look.
- Codex and opencode keep no record of running sessions; which process has
  which chat open is matched from process inspection, and from the process
  a session's hook ran under once hooks are installed.
- After you approve a prompt, no agent reports it; see |agent-chats-status|.
- Developed and tested on Linux. The path for systems without /proc is
  exercised by the tests but has not run on a Mac. Windows is untested and
  the shell hooks need a POSIX `sh`.
- The agents' file formats are not public interfaces and may change.
